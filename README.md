# Multi-Agent Orchestration System

A multi-agent AI system using LangChain and Langgraph with intelligent task routing, specialized agent execution, and comprehensive performance monitoring. It is capable of generating and executing code.

## WARNING

This system code is generated by an AI code agent and the code it generates is also from an AI LLM. When it comes to code execution there is no-human-in-the-loop.

The primary purpose of this exercise is to learn how wire and route AI agents. Therefore, no fact checks on responses from the inference and LLM. However, there was one undesirable output but it was an interesting point to note that when the prompt did not ask the LLM not to invent facts nor mocked data was provided, a fictional analysis was made up.

```text
It is autonomous in nature, using a restricted and bounded sandbox is highly recommended for containment and security purposes. Also, run the code with a role with limited and unelevated access.
```

> Note that the model used in this multi-agent example is llama2:13b-chat-q4_K_M, which is capable of generating code. However, for better code quality, use a larger model. This code was tested in CPU-only mode (i.e. no CUDA or TPU was used), it showed the time taken from start to fininsh was about 5 minutes on an Apple M1 silicon with 16Gb of RAM. The model alone used about 8Gb of RAM.

## 🎯 Core Design Principles

### 1. **Intelligent Routing**
The Router Agent analyzes incoming tasks and dynamically selects the most appropriate specialist:
- **Complexity Assessment**: Evaluates task difficulty (0.0 - 1.0 scale)
- **Domain Matching**: Matches task keywords to agent expertise
- **Confidence Scoring**: Provides confidence level for routing decision
- **Fallback Mechanisms**: Graceful degradation if primary routing fails

### 2. **Specialist Agent Pattern**
Each specialist agent is designed with:
- **Focused Expertise**: Deep knowledge in specific domain
- **Clear Responsibilities**: Well-defined tasks and capabilities
- **Consistent Interface**: Standardized execution and metrics collection
- **Error Isolation**: Failures don't cascade to other agents

### 3. **State Management**
Comprehensive state tracking throughout execution:
- **Message History**: Maintains conversation context
- **Task Metadata**: Tracks task type, complexity, routing decisions
- **Error Tracking**: Captures and logs issues at each step
- **Performance Data**: Collects latency and token metrics

### 4. **Performance Monitoring**
Built-in metrics collection for optimization:
- **Per-Agent Latency**: Time taken by each agent to execute
- **Token Usage**: Estimated tokens consumed per agent
- **Routing Overhead**: Time spent in routing decision
- **Total Workflow Time**: End-to-end execution time

## 🔄 Workflow Execution Flow

### Step 1: Task Ingestion
```python
task = "Generate a Python function to analyze CSV files"
state = AgentState(
    task=task,
    task_id="abc123",
    messages=[HumanMessage(content=task)]
)
```

### Step 2: Routing Decision
The Router Agent receives the task and determines:
- Task type and complexity
- Best matching specialist agent
- Confidence and reasoning

**Example Routing Decision**:
```json
{
    "selected_agent": "code_generator",
    "complexity_score": 0.65,
    "reasoning": "Task requires code generation with data file handling",
    "confidence": 0.92
}
```

### Step 3: Specialist Execution
Selected agent executes with:
- System prompt injection for domain expertise
- LLM invocation with full message history
- Response generation and formatting
- Automatic performance metrics collection

### Step 4: Metrics Collection
Each execution records:
```python
PerformanceMetrics(
    agent_type=AgentType.CODE_GENERATOR,
    latency_ms=1234.56,
    tokens_used=2156,
    task_id="abc123",
    timestamp=1695234567.89
)
```

### Step 5: Output Formatting
Final state includes:
- Agent's response/result
- Full message history
- Performance report
- Routing information
- Error details (if any)

## 🛡️ Error Handling & Fallback Mechanisms

### Routing Fallback Strategy

If JSON parsing fails or LLM returns invalid agent type:
1. **Keyword Matching**: Check task for domain keywords
2. **Default Agent**: Fall back to Planner agent
3. **Confidence Reduction**: Mark as lower-confidence routing
4. **Error Logging**: Record fallback usage for monitoring

**Keyword Mapping**:
```python
{
    "code": CodeGeneratorAgent,
    "debug": CodeGeneratorAgent,
    "data": DataAnalystAgent,
    "analyze": DataAnalystAgent,
    "plan": PlannerAgent,
    "task": PlannerAgent,
}
```

### Execution Error Handling

- **Try-Catch Blocks**: Wrap all LLM invocations
- **State Preservation**: Maintain state even on error
- **Error Logging**: Detailed error messages and stack traces
- **Graceful Degradation**: Return partial results when possible

## 🚀 Usage Example

```python
import asyncio
from multi_agent_system import MultiAgentOrchestrator

async def main():
    # Initialize orchestrator
    orchestrator = MultiAgentOrchestrator()
    
    # Process task
    task = "Generate a Python function to analyze CSV files"
    result = await orchestrator.process_task(task)
    
    # Print results
    print(f"Result: {result.result}")
    print(f"Selected Agent: {result.selected_agent}")
    print(f"Complexity: {result.complexity_score:.2f}")

asyncio.run(main())
```

### Model Specifications

**Recommended Model**: Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf
- **Size**: ~5GB (quantized Q4)
- **Performance**: Excellent quality with fast inference
- **Memory**: ~8GB RAM required
- **Speed**: ~10-20 tokens/second on CPU

**Alternative Models**:
- Llama-2-7B-Chat-GGUF (smaller, faster)
- Mistral-7B-Instruct-GGUF (better instruction following)
- Neural-Chat-7B-GGUF (optimized for conversations)

### Performance Tuning

**For GPU Acceleration** (CUDA):
```bash
CMAKE_ARGS="-DLLAMA_CUDA=on" pip install llama-cpp-python --force-reinstall --no-cache-dir
```

**For Metal Support** (macOS):
```bash
CMAKE_ARGS="-DLLAMA_METAL=on" pip install llama-cpp-python --force-reinstall --no-cache-dir
```

**Optimization Parameters**:
```python
llm = LlamaCpp(
    model_path="./models/llama-2-7b-chat.Q4_K_M.gguf",
    n_gpu_layers=35,        # Offload 35 layers to GPU

    n_batch=512,            # Batch size for processing
    n_ctx=2048,             # Context window size
    f16_kv=True,            # Use float16 for KV cache
    verbose=False
```
